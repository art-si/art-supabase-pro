# Creative Direction For New Or Reshaped UI

Read this only for Create mode or a substantial redesign with open visual decisions. Project identity still outranks novelty.

## Ground The Direction

State a compact design premise before coding:

- **Operator**: who uses this workflow and under what pressure.
- **Job**: the single decision or action the page must make easier.
- **Tone**: choose two or three compatible qualities, such as precise, calm, and decisive.
- **Density**: low, medium, or high based on task frequency and data volume.
- **Signature**: one memorable, useful treatment that expresses the workflow.

Choose the signature from the business subject rather than a generic trend. Examples include an exception-risk strip, route progress spine, reconciliation balance bridge, audit evidence rail, or compact operational command header.

## Set The Design Dials

Use a 1–5 scale and record the decision internally:

- **Density**: default 4 for recurring enterprise operations; lower it for onboarding or explanation-heavy pages.
- **Expressiveness**: default 2; raise it only when the workflow or supplied reference supports stronger identity.
- **Motion**: default 1; raise it only when motion explains progress, spatial movement, or state transition.
- **Contrast**: default 3; increase emphasis through hierarchy before adding new colors.

Do not make all dials high. Spend visual distinctiveness in one place and keep the rest quiet.

## Compose Before Decorating

Sketch the structure before styling:

1. Page identity and primary action.
2. Decision summary or risk/status context.
3. Main task surface.
4. Supporting evidence and audit details.

Compare at least two plausible compositions mentally or with a compact wireframe. Choose the one that shortens the user's scan and action path, not the one with more visual effects.

## Typography, Color, And Data

- Use the project font stack unless brand work explicitly authorizes a change.
- Create personality through scale, weight, spacing, alignment, and data formatting before introducing a new typeface.
- Use the project neutral scale and theme color. Add no page-local palette unless the user supplies a new brand system.
- Let numbers, status, sequence, and relationships carry the visual concept when the workflow is data-heavy.
- Use charts only when they improve comparison, trend, distribution, or progress comprehension.

## Avoid Generic AI Styling

- Do not default to oversized gradient heroes, glowing purple cards, glass panels, decorative metric grids, or arbitrary bento layouts.
- Do not add eyebrows, numbered sections, pills, or icons unless they encode real information.
- Do not fill blank space with decoration that competes with operations.
- Do not imitate a marketing landing page inside an authenticated enterprise workspace.

## Self-Critique Before Building

Ask:

1. Could this composition belong unchanged to an unrelated admin product?
2. Does the signature element encode something true about this workflow?
3. Is the primary action obvious without explanatory prose?
4. Can one decorative element be removed without losing meaning?
5. Does the proposal remain coherent in dark mode, narrow desktop, loading, empty, and error states?

Revise any generic or unsupported choice before implementation.
