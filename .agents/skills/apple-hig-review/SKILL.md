# Apple HIG Review

Use [dickwu's review workflow](https://github.com/dickwu/apple-design-skill/blob/main/SKILL.md) and its [HIG index](https://github.com/dickwu/apple-design-skill/blob/main/references/hig-lookup.md). Start with the operator's task, the actual platform, and the available evidence. Read only the relevant current Apple pages; common starting points are [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), and [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars).

For a browser workspace, translate principles to Web behavior and check visible focus, contrast over the backing surface, dark-mode legibility, selection, and overlays. Use the repository's `professional-ui-quality` rubric and Web thresholds. Native menu, window, keybinding, and control-size conventions are context, not requirements for ordinary Web pages.

Record what is visible, why it matters, the smallest compatible fix, and how to verify it. Measure from real styles or the rendered page rather than estimating contrast from a screenshot. Preserve business behavior, component ownership, and density. A review request authorizes findings.
