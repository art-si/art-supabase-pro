# TreeUtils 使用边界

`tree.ts` 是菜单、字典、组织和业务选择器共用的结构工具。业务组件不应另写同类扁平化、路径或循环检测算法。

## 数据与引用契约

- `listToTree` 处理**扁平列表**，仅以配置的父 ID 重建 children，忽略残留嵌套 children，避免重复挂载。输入已经是嵌套树时使用 `normalizeTreeData`，不能将两者混用。
- 保留既有兼容规则：重复 ID 最后一条生效；找不到父节点时保留为根；默认根标记是 `null/undefined/0/''`。这不是判断数据库根节点的规则，后端根查询仍应明确约束 `parent_id IS NULL`。
- `normalizeTreeData` 接受数组或 JSON 数组，过滤非对象条目，去掉非法 children。无效 JSON/非数组仍返回空数组；循环对象结构会抛出 `TreeDataError`，不能冒充空数据。
- `treeToList` 按先序输出，保留业务父 ID，不复制 children。默认深拷贝业务字段；`deepClone: false` 时嵌套业务字段仍共享引用，结构数组不因此写回原输入。
- `findNode` 返回输入树中的第一个匹配引用，不克隆。需要修改副本时先明确使用复制操作，不能将此方法误认为隔离编辑数据。
- `traverse` 使用输入引用；每次回调得到独立的祖先 ID 数组，返回 `false` 立即停止。
- 同一个对象出现在不同非循环分支时保留两条路径，不把这种共享关系误判为循环。
- `updateNode/addNode/removeNode/sortTree/sortTreeByField/removeNodesByCondition` 始终复制节点和 children 数组；`deepClone: false` 只允许嵌套业务字段共享引用，不再把树结构写回原数据。新增子树和更新补丁中的 children 同样独立复制并检查循环；默认深拷贝时补丁业务字段也隔离。
- `updateNode` 按查找先序更新第一个匹配；`removeNode` 保留原有逆兄弟顺序查找约定，删除整个子树。ID 应唯一，重复 ID 不应作为业务选择机制。未匹配时仍返回独立树和 `null`。
- 条件删除只回调保留路径；匹配祖先后不再回调其后代，`removed` 保存完整被移除子树。排序比较函数、删除条件和映射回调应只读取结构，不能在回调中修改 children 或引入循环。
- 字段排序复用 `sortTree` 与 lodash `get`，支持嵌套路径；空值在升降序中均置后，两个空值保持原相对顺序。自定义比较函数优先。
- `mapTree` 先复制并验证整棵树一次，再按先序执行映射。回调可读取原节点 children，返回对象的 children 仍由输入层级重建，叶子为 `[]`；回调不得修改传入子树。默认深拷贝隔离业务字段，浅模式保持原业务字段共享。不会再为每个祖先单独深拷贝整棵子树。
- `mapTree<T, TResult>` 支持输入、输出使用不同业务类型，例如将部门 DTO 映射为下拉选项；层级由工具保留，无需在业务组件中递归或断言输入已是选项类型。
- `getDescendants` 返回先序**平面节点列表，不含 children**，第三个参数控制是否包含自身。`getAncestors` 返回根到目标（含自身）的平面列表，不含 children；依据实际访问路径，避免重复 ID 把其他分支混入面包屑。目标不存在均为 `[]`。
- `getLabelPathIndex(tree, resolveLabel, separator)` 一次遍历生成 ID 到展示路径的 `Map`，默认分隔符为 `/`。不修改输入；重复 ID 保留先序首次路径，与 `getAncestors` 的查找顺序一致。结果是快照，树、标题或语言变化后应重新构建。菜单展示使用 `createMenuPathResolver`，并在 `computed` 内绑定当前菜单树，避免逐行重复遍历和拷贝祖先节点。

### 祖先/后代结果契约调整

此前这两个查询在平面列表的每条记录里重复附带完整子树，深链有平方级复制量。本次明确改成与 `treeToList` 一致的字段级复制。已核对当前主仓与子仓调用：菜单删除检查、字典折叠/拖拽、组织范围/计数、编号面包屑、MDM 生产部门、HR 人员岗位、SMIS 场所及类别选择均只使用节点字段，不读取查询结果中的 children，无需改动调用表达式。后续新增调用必须遵守此约定。

需要完整子树时，使用 `findNode` 找到引用，再用 `normalizeTreeData([node])` 获取独立副本；不要通过祖先/后代平面查询间接获取嵌套结构。两个平面查询默认深拷贝业务字段；浅模式仅共享嵌套业务字段，不共享返回记录对象。

## 可靠性与复杂度

已将规范化、平面建树及排序、扁平化、查找、遍历、路径和父链循环检测改为迭代实现。扁平化不再重复深拷贝每个祖先的整棵子树；循环返回稳定 `TREE_CYCLE` 错误和中文说明。

普通结构扫描是线性访问；排序另有排序成本，业务字段深克隆成本由字段大小决定。启用完整祖先数组输出时，输出量本身可能达到所有节点深度之和，不能宣称所有参数组合都为 O(n)。

新增、更新、删除、条件删除及两种排序也已移除结构递归和整树 `cloneDeep`，在调用比较或条件函数前完成输入结构验证。浅拷贝模式的结构隔离是有意修复，不能再依赖此前意外的原树副作用。

映射与祖先/后代查询也已整合：映射按节点复制业务载荷，后代访问所选分支，祖先查询只扫描到目标再反向收集父链，不再为每个 ID 重扫整棵树。提前结束的查找/祖先查询只检查实际经过的结构，不承诺检查未访问分支；完整输入检查使用 `normalizeTreeData`。深度保证仅覆盖 children 结构；任意深层业务字段仍受 lodash 深拷贝限制。也不代表 Element Plus 能渲染 12,000 层嵌套树；深树单测验证的是数据工具，不是 UI 展开能力。

## 错误处理与验证

调用者应将 `TreeDataError` 送入加载失败状态，不记录原始人员/菜单载荷，不显示成功空列表。字典目录已经提供失败/循环提示及重新加载；菜单管理、角色权限已有对应 catch 路径。其余消费者需要继续核对错误、恢复及写入期间状态。

- `tests/unit/tree.test.ts`：12,000 层读取及编辑、150,000 同级节点、循环及回调前拒绝、根标记、重复输入、浅/深引用隔离、补丁隔离、删除语义、空值排序、独立祖先路径、提前退出及载荷克隆次数。
- `tests/e2e/dictionary-tree-state.spec.ts`：合成异常/失败/空/正常目录，验证状态和重试，无业务写入。
- `tests/e2e/dictionary-cascade-query.spec.ts`：真实只读接口及列表加载。
- `tests/e2e/role-permission-state.spec.ts`：权限树状态、滚动和保存隔离，所有保存均拦截。
- `tests/e2e/menu-management.lazy-tree.spec.ts`：真实根/子查询与详情面包屑，根数依据接口结果，不依赖固定菜单数量。
