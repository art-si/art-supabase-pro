# 工序报工与自动完工入库

## 业务规则

- 工序任务展板双击和生产工单号共用现有只读工单详情弹窗，遵守工单查看权限与当前租户范围。
- 主序列首道工序保留开始加工；其余工序直接报工，不人为生成开始时间。
- 报工页面通过 `mes_execution_task_rules` 读取当前任务的必要规则，不依赖完整工单查看权限；接口仍检查报工查看权限与租户范围。
- 报工提交仍进入待审批。审批通过才更新产量并执行控制码副作用；驳回不触发补报和入库。
- SY06 为必须汇报工序。确认后按工序计划数量比例，将同一序列的前道补至当前累计确认产量。
  已确认数量和待审批人工报工均扣除，已有记录不覆盖，独立并行序列不自动完成。
  后续工序不能绕过同序列前道的必须汇报节点，即使后续节点本身未启用严格顺序控制。
- 每条系统补报注明“系统自报工”，关联来源报工；没有实际开始时间或操作人员时不伪造工时。
- 仅最后一道主序列工序的 SY05 确认触发完工入库。工单累计确认、已入库以及未办理入库单的数量分别核算。
- 用户确认：尚未选择汇总或按包模式的工单先生成草稿，由业务人员选择；不自动锁定首次模式。
- 已固定模式沿用原模式。仓库、单位、单据类型、初始化等资料齐全且无需指定仓位/序列号时可自动提交、审核和入库。
  既有完全领料、在制扣减、库存单位换算和库存校验继续执行；可恢复的业务阻挡保留草稿。
- 按包模式仅在已发布、未入库且未被占用的完整包数量匹配时自动入库，否则留待选包。不会降级成汇总库存。

## 状态与来源

| 记录 | 合法流转 | 管理边界 |
| --- | --- | --- |
| 人工报工 | 待审批 → 已审批 / 已驳回；驳回后重提 | MES 报工与审批权限 |
| 系统补报 | 来源人工报工审批成功时创建为已审批 | `system_source_report_id` 关联同工单来源 |
| 自动入库草稿 | 暂存 → 补全 → 提交 → 审核 → 入库 | 原 WMS 单据流程 |
| 资料齐全自动入库 | 暂存 → 提交 → 审核 → 入库 | 私有系统入口复用 WMS 校验与过账 |

`wms_production_material_document.source_report_id` 唯一关联来源报工；`source_report_quantity`
记录本单可入库上限（工单生产单位）。来源、上限和工单不可换绑。只允许有来源的系统草稿暂缺仓库或类型，
普通单据及提交后的单据继续要求完整表头。没有明细的系统草稿也出现在原完工入库列表中。

所有自动动作位于报工确认事务中，先锁工单再锁报工/任务，重复确认受状态及唯一来源约束拦截。
自动入口仅存在于私有 schema，撤销匿名和普通认证角色的直接执行权限；普通审批人员通过 MES 审批触发，
不额外要求通用库存过账按钮权限。普通用户伪造租户头不能获得跨租户能力。
