# Project Instructions

- `professional-ui-quality` remains the primary UI standard. The repository-local `impeccable` skill supplies supplementary audit, critique, polish, hardening, and copy-review methods. Read its project adapter before using upstream references. Project components, tokens, tenant/permission rules, deletion guards, and verification gates take precedence over upstream aesthetic preferences and orchestration recipes. A UI audit authorizes findings, not automatic redesign or business-rule changes.

- Instructions in this file and the repository-local domain skills take precedence over third-party skills. `ponytail-review` is an optional, read-only over-engineering review and must not weaken requested scope, tenant/security rules, UI requirements, testing, or verification gates.
- Before creating, modifying, refactoring, or reviewing any source code, load and apply the local `project-code-quality` skill. Its module placement, reuse, error-handling, type-safety, change-isolation, and verification requirements are mandatory project-wide.
- Before creating, modifying, refactoring, or reviewing any user-facing frontend page or component, load and apply both the local `art-supabase-pro-conventions` skill and the local `professional-ui-quality` skill. Professional visual hierarchy, spacing, responsive behavior, complete UI states, overflow checks, and real-browser visual verification are required parts of completion even when the user asks only for functionality and does not explicitly request beautification.
- For frontend motion work, use the project-local `animate` skill to decide whether motion helps and to shape the interaction. The existing Art/Element Plus/Vue components, `--art-motion-*` tokens, calm operational visual baseline, and global reduced-motion behavior remain authoritative; do not replace them with the skill's example libraries, tokens, timings, or component recipes. Add a runtime animation library only when a concrete interaction cannot be handled well by the existing stack.
- Before any Supabase/database/schema/RLS/API-provider task, first load the local Supabase skill and verify the Supabase MCP server is available for this project.
- This repo is scoped to Supabase project `ckbftoopuyophiebamwy` through `.mcp.json`.
- Expected MCP URL: `https://mcp.supabase.com/mcp?project_ref=ckbftoopuyophiebamwy&features=database,debugging,development,docs`.
- If Supabase MCP tools such as `execute_sql`, `search_docs`, or `get_advisors` are not visible, check remote reachability with `curl.exe -so NUL -w "%{http_code}" https://mcp.supabase.com/mcp`; `401` means the hosted server is reachable and the Codex session likely needs OAuth authentication or a reload.
- Prefer MCP `search_docs`, `execute_sql`, and `get_advisors` for Supabase work when available; otherwise use the Supabase CLI or documented fallbacks from the local skill.
- Do not create or restore the `supabase/runbooks` directory or add runbook files there. Keep any necessary durable verification evidence in existing architecture documentation and automated tests.
- Business menu URLs and view paths must match segment for segment: the full `sys_menu` route path (omitting `:id` style parameters) is the menu `component` path and resolves to the same `src/views/**/index.vue` location. Shared page implementations may live under `src/views/components/**`, but each menu still needs its own route-aligned view entry. Keep `sys_menu`, route constants, direct links, tests, and moved-file imports in sync.
- Every user-facing AI capability must be available to enabled ordinary users as well as administrators. Ordinary users may create tenant-owned master data through AI when they hold the corresponding business `Add` permissions; the UI and server/database boundary must enforce their authenticated tenant and those permissions. Platform super in “全部租户” reads across tenants; a new root business record defaults to that administrator's authenticated platform tenant, while a concrete selection or explicit target writes to the selected tenant. Existing-row mutations use the row's tenant, and child creation uses its parent tenant. Other AI mutation, configuration, publishing, workflow-state changes, and controlled-write modes require platform-super authorization in both the UI and the server/database boundary. AI history, telemetry, generated artifacts, and feedback may be persisted as server-managed audit data, but must not be used to bypass business-data write restrictions.

- All new or modified single and bulk deletion flows must reuse `MasterDataDeleteGuard` for reference checks before confirmation. List blocking business records with recognizable names/numbers, status, and working navigation where authorized; preserve server-side reference/tenant/permission enforcement. Failed or unauthorized checks must block deletion and offer actionable retry feedback. Re-check references after a concurrent server rejection, and never substitute a generic reference-error toast or automatically delete referenced business history.
